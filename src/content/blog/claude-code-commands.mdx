פקודות Claude Code הן פקודות שמתחילות בלוכסן (/) ומנהלות את השיחה עצמה: מחליפות מודל, מנקות הקשר, נכנסות למצב תכנון, מחזירות שינויים אחורה או בודקות את הקוד לפני שמסיימים. הכי שימושיות ביום יום הן `/init`, `/clear`, `/compact`, `/context`, `/plan`, `/rewind`, `/diff` ו-`/code-review`. כדי לראות את כל מה שזמין לכם, מקלידים `/` בשורה ריקה.

<div class="definition">**פקודה (Slash command):** הוראה שמתחילה ב-`/` ונשלחת בתחילת הודעה ב-Claude Code. לפי התיעוד, חלק מהפקודות מובנות בכלי עצמו, וחלקן Skills מובנים, כלומר הוראות ש-Claude מקבל ומבצע. כל טקסט שבא אחרי שם הפקודה עובר אליה כפרמטר.</div>

המדריך מניח ש-Claude Code כבר מותקן אצלכם. אם לא, התחילו מהמדריך [איך מתקינים Claude Code](/blog/how-to-install-claude-code).

## איך מפעילים פקודה ב-Claude Code?

מקלידים `/` בתחילת ההודעה. נפתח תפריט, וכל אות שמוסיפים מסננת אותו: `/com` כבר מציג את `/compact`. Enter מריץ את ההצעה המודגשת, ו-Tab משלים אותה.

שלושה כללים שכדאי להכיר:

- **רק בתחילת ההודעה.** פקודה באמצע משפט היא סתם טקסט.
- **מה שבא אחרי הפקודה הוא פרמטר.** למשל `/plan fix the login bug` נכנס למצב תכנון ומתחיל מיד במשימה.
- **פקודה שנשלחת בזמן ש-Claude עובד מחכה בתור** עד שהתור שלו מסתיים. חלק מהפקודות, כמו `/status` ו-`/usage`, רצות מיד בלי לעצור אותו.

לא כל פקודה מופיעה אצל כולם. התיעוד מציין שהזמינות תלויה במערכת ההפעלה, במסלול ובסביבה. אם פקודה מהמדריך חסרה אצלכם, עדכנו את הכלי עם `claude update`.

## אילו פקודות Claude Code הכי שימושיות?

אלה הפקודות שחוזרות כמעט בכל סשן עבודה, עם התיאור שלהן לפי התיעוד הרשמי:

| פקודה | מה היא עושה | מתי משתמשים |
|---|---|---|
| `/init` | יוצרת קובץ `CLAUDE.md` ראשוני לפרויקט | בפעם הראשונה בפרויקט חדש |
| `/memory` | עריכת קובצי `CLAUDE.md` וניהול הזיכרון האוטומטי | כשרוצים ש-Claude יזכור כלל קבוע |
| `/permissions` | כללי אישור, שאלה וחסימה לכלים | כשנמאס לאשר את אותה פעולה שוב ושוב |
| `/plan` | נכנסת למצב תכנון לפני שינוי גדול | לפני משימה שנוגעת בהרבה קבצים |
| `/model` | מחליפה מודל ושומרת אותו כברירת מחדל | כשהמשימה דורשת מודל אחר |
| `/context` | מציגה מה ממלא את חלון ההקשר | כשהשיחה ארוכה ו-Claude מתחיל לשכוח |
| `/compact` | מסכמת את השיחה כדי לפנות מקום | ממשיכים באותה משימה ונגמר המקום |
| `/clear` | שיחה חדשה עם הקשר ריק | עוברים למשימה אחרת |
| `/resume` | חוזרת לשיחה קודמת לפי שם או מתוך רשימה | ממשיכים עבודה מאתמול |
| `/rewind` | מחזירה קוד ושיחה לנקודת שמירה קודמת | Claude הלך לכיוון לא נכון |
| `/diff` | מציגה מה השתנה בקבצים, כולל העריכות של Claude | לפני שמאשרים ושומרים |
| `/code-review` | בודקת את השינויים ומחפשת באגים | לפני commit או pull request |
| `/usage` | עלות הסשן ומגבלות השימוש של המסלול | כשרוצים לדעת כמה נשאר |
| `/doctor` | בדיקת התקנה והגדרות, עם הצעות לתיקון | כשמשהו לא עובד כמו שצריך |

## איך שומרים על שיחה ארוכה בלי לאבד הקשר?

כל מה שנאמר בשיחה, וכל קובץ ש-Claude קרא, תופס מקום ב[חלון ההקשר](/glossary/context-window), וכשהוא מתמלא צריך לפנות מקום כדי להמשיך. ארבע פקודות מטפלות בזה:

1. **`/context` כדי לראות את המצב.** הפקודה מציגה רשת צבעונית של מה שממלא את החלון, עם הצעות מה אפשר לחסוך.
2. **`/compact` כדי להמשיך.** Claude מסכם את השיחה עד עכשיו וממשיך מהסיכום. אפשר לכוון את הסיכום: `/compact focus on the API changes`.
3. **`/clear` כדי להתחיל מחדש.** שיחה חדשה עם הקשר ריק. ההוראות מ-`CLAUDE.md` נטענות שוב, והשיחה הקודמת זמינה ב-`/resume`.
4. **`/btw` לשאלה צדדית.** שואלים משהו על הסשן בלי שהשאלה והתשובה ייכנסו להיסטוריה של השיחה.

הכלל הפשוט: משימה חדשה פותחים ב-`/clear`. שיחה שמערבבת כמה משימות מכניסה להקשר מידע שלא קשור למה שאתם עושים עכשיו. הוראות שאתם חוזרים עליהן בכל שיחה כדאי להעביר לקובץ, כמו שמוסבר במדריך [קובץ CLAUDE.md](/blog/how-to-write-claude-md).

## איך מתקנים טעות או חוזרים אחורה?

Claude Code שומר נקודות שמירה בזמן העבודה, ולכן טעות היא לא סוף העולם:

- **Esc** עוצר את Claude באמצע תשובה או פעולה. לפי התיעוד, העבודה שנעשתה עד אותו רגע נשמרת, ואפשר לתת הנחיה אחרת.
- **Esc פעמיים בשורה ריקה**, או `/rewind`, פותחים תפריט שמחזיר את הקוד, את השיחה או את שניהם לנקודה קודמת.
- **`/branch`** יוצרת עותק של השיחה מהנקודה הנוכחית, כדי לנסות כיוון אחר בלי לאבד את מה שיש. חוזרים למקור עם `/resume`.
- **`/doctor`** מריצה בדיקה של ההתקנה, ההגדרות וקובץ `CLAUDE.md`, ומציעה תיקונים ש-Claude מבצע אחרי שתאשרו.

## אילו קיצורי מקלדת כדאי לזכור?

מעבר לפקודות, יש כמה קיצורים שחוסכים הרבה הקלדה:

- **Shift+Tab** עובר בין מצבי ההרשאות: מצב רגיל שבו Claude שואל לפני כל שינוי, מצב שבו עריכות קבצים מאושרות אוטומטית, ומצב תכנון שבו Claude רק מתכנן ולא נוגע בקבצים.
- **`!` בתחילת השורה** מריץ פקודת טרמינל ישירות, ומוסיף את הפלט שלה לשיחה כדי ש-Claude יגיב עליו.
- **`@`** פותח השלמה אוטומטית של נתיבי קבצים, כדי להפנות את Claude לקובץ מסוים.
- **Ctrl+V** מדביק תמונה מהלוח. ב-Windows משתמשים ב-Alt+V, ובטרמינל iTerm2 ב-Cmd+V.
- **Ctrl+R** מחפש בהודעות קודמות שכתבתם.

## אילו פקודות מריצים בטרמינל, לפני שנכנסים?

חלק מהעבודה מתחיל עוד לפני שהשיחה נפתחת. אלה פקודות שמקלידים בטרמינל הרגיל:

| פקודה | מה היא עושה |
|---|---|
| `claude` | פותחת שיחה חדשה בתיקייה הנוכחית |
| `claude "explain this project"` | פותחת שיחה עם הודעה ראשונה |
| `claude -c` | ממשיכה את השיחה האחרונה בתיקייה הזו |
| `claude -r "name"` | חוזרת לשיחה מסוימת לפי שם או מזהה |
| `claude -p "query"` | שולחת שאלה אחת, מדפיסה תשובה ויוצאת |
| `claude update` | מעדכנת לגרסה האחרונה |
| `claude doctor` | בדיקת התקנה והגדרות בלי לפתוח שיחה |

`claude -p` שימושי במיוחד בסקריפטים: אפשר להעביר אליו קובץ דרך צינור, למשל `cat logs.txt | claude -p "explain"`.

## איך נראה סשן עבודה טיפוסי עם הפקודות?

התיעוד של Claude Code מסדר את הפקודות לפי שלבי העבודה. בתרגום לסשן אחד:

1. **פרויקט חדש:** `/init` יוצר `CLAUDE.md` ראשוני, ו-`/memory` מאפשר לחדד אותו.
2. **הגדרות:** `/permissions` קובע מה Claude עושה בלי לשאול, ו-`/mcp` מחבר כלים חיצוניים.
3. **לפני שינוי גדול:** `/plan` ותיאור המשימה. קוראים את התוכנית לפני שמאשרים.
4. **תוך כדי:** `/context` כשהשיחה מתארכת, ו-`/compact` כשצריך מקום.
5. **לפני שמסיימים:** `/diff` כדי לראות מה השתנה, ו-`/code-review` כדי לחפש באגים. בשינוי שנוגע בהרשאות או במידע רגיש, גם `/security-review`.
6. **משימה הבאה:** `/clear`, ומתחילים נקי.

## איך יוצרים פקודה משלכם?

כל [Skill](/blog/claude-skills-guide) שאתם כותבים הופך לפקודה. שמים תיקייה עם קובץ `SKILL.md` ב-`.claude/skills/` בתוך הפרויקט, או ב-`~/.claude/skills/` לשימוש אישי, והוא זמין כפקודה: `/` ושם ה-Skill. לפי התיעוד, אפשר גם לפתוח הודעה אחת בכמה Skills ברצף, וכל אחד מהם מקבל את הטקסט שבא אחריהם.

`/skills` מציג את כל ה-Skills שזמינים לכם, ו-`/reload-skills` טוען מחדש Skills שהוספתם או שיניתם בלי להפעיל את הכלי מחדש. התחילו מתהליך שאתם מסבירים ל-Claude שוב ושוב, כמו בדיקה לפני שחרור או כתיבת הודעת commit לפי הכללים של הצוות.

## אילו טעויות נפוצות כדאי להכיר?

- **`/clear` כשהתכוונתם ל-`/compact`.** `/clear` מתחיל שיחה ריקה. אם רציתם להמשיך את אותה משימה, חזרו לשיחה הקודמת עם `/resume`.
- **פקודה באמצע משפט.** "תריץ /compact בבקשה" לא מפעיל כלום. הפקודה חייבת לפתוח את ההודעה.
- **שיחה אחת לכל היום.** הקשר מלא בשאריות של משימות קודמות תופס מקום ומסיח את Claude ממה שחשוב עכשיו. משימה חדשה, שיחה חדשה.
- **לדלג על `/diff`.** גם כש-Claude אומר שסיים, כדאי לראות מה בדיוק השתנה לפני שמאשרים.
- **להסתמך על רשימה ישנה.** הכלי מתעדכן לעתים קרובות, פקודות מתווספות ומשתנות. `/help` ו-`/release-notes` מראים מה קיים אצלכם עכשיו.

עוד מדריכים על הכלי נמצאים במרכז הנושא [Claude Code](/topics/claude-code), ואם אתם לא מתכנתים, התחילו מ-[Claude Code למי שלא מתכנת](/blog/claude-code-for-non-developers).
