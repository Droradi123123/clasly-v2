מדריך n8n למתחילים צריך לענות על שלוש שאלות: איפה מריצים את n8n, אילו מושגים צריך להכיר, ואיך בונים את ה-workflow הראשון. התשובה הקצרה: מתחילים בענן, לומדים שמונה מושגים, ובונים workflow של ארבעה צמתים שרץ כל בוקר, מביא נתונים, מעבד אותם ושומר אותם בטבלה. אחרי workflow אחד כזה, כל אוטומציה אחרת היא אותו דפוס עם צמתים אחרים.

<div class="definition">**n8n:** כלי לבניית אוטומציות, שבו מחברים צמתים לזרימת עבודה (workflow). כל צומת עושה פעולה אחת: מתחיל את התהליך, מביא נתונים, מעבד אותם או שולח אותם למערכת אחרת. לפי התיעוד של n8n, workflow רץ צומת אחרי צומת, ויכול להתפצל, להתאחד ולחזור על עצמו.</div>

המדריך מבוסס על התיעוד הרשמי של n8n, ומסביר אותו בעברית. אם אתם עוד מתלבטים אם n8n הוא הכלי הנכון, ראו קודם [n8n לעומת Make ו-Zapier](/blog/n8n-vs-make-vs-zapier-for-ai). התמונה הרחבה של n8n בארגון נמצאת במרכז הנושא [n8n ואוטומציה](/topics/n8n).

## מה צריך לפני שמתחילים עם n8n?

צריך סביבה של n8n. התיעוד מציע שתי דרכים, וממליץ להחליט לפי המצב שלכם:

| המצב שלכם | מה מומלץ | למה |
|---|---|---|
| רוצים להתחיל מיד | n8n Cloud | אין התקנה |
| אין לכם ידע טכני | n8n Cloud | מנוהל לגמרי, בלי התקנה ותחזוקה |
| צריכים שליטה מלאה בסביבה | שרת משלכם | אתם קובעים את ההגדרות |
| רוצים להריץ בחינם | שרת משלכם, מהדורת Community | חינם, עם כמעט כל היכולות |
| צריכים סביבה לפרודקשן | שתי האפשרויות | שתיהן תומכות בשימוש בפרודקשן |

למתחילים ההמלצה פשוטה: תקופת ניסיון בענן. כשתדעו מה אתם בונים ואם צריך שרת משלכם, תחליטו. את שאלת ההתקנה נשאיר למדריך נפרד.

## אילו מושגים צריך להכיר במדריך n8n למתחילים?

שמונה מושגים, לפי מילון המושגים של n8n. כמעט כל שאלה של מתחילים חוזרת לאחד מהם:

| מושג | מה זה |
|---|---|
| Workflow | אוסף צמתים שמבצע תהליך. מתחיל כשטריגר מופעל, כשמריצים אותו ידנית, או כש-workflow אחר קורא לו |
| צומת (Node) | רכיב אחד בזרימה: מתחיל אותה, מביא או שולח נתונים, מעבד אותם או מתחבר לשירות חיצוני |
| טריגר (Trigger node) | הצומת שמתחיל את ה-workflow בתנאי מסוים. כל workflow שרץ לבד צריך לפחות טריגר אחד |
| Credential | פרטי ההתחברות לשירות, כמו סיסמה, מפתח API או הרשאת OAuth, שהצמתים משתמשים בהם |
| ביטוי (Expression) | ערך דינמי בפרמטר של צומת, שנלקח למשל מהפלט של צומת קודם |
| הרצה (Execution) | ריצה אחת של workflow, ידנית מהעורך או אוטומטית כשהטריגר מופעל |
| פרסום (Publish) | הפעלת גרסה של ה-workflow בפרודקשן. רק הגרסה המפורסמת רצה כשהטריגר מופעל |
| נעיצת נתונים (Data pinning) | הקפאת הפלט של צומת בזמן הפיתוח, כדי לא לקרוא שוב ושוב לשירות חיצוני. בפרודקשן מתעלמים ממנה |

אם תזכרו רק דבר אחד: טריגר קובע מתי, הצמתים קובעים מה, ופרסום קובע אם זה רץ באמת.

## איך בונים את ה-workflow הראשון ב-n8n, צעד אחרי צעד?

<figure><a href="/blog/n8n-beginners-guide/first-workflow.png"><img src="/blog/n8n-beginners-guide/first-workflow.png" alt="ה-workflow הראשון ב-n8n בארבעה צמתים: טריגר, Schedule Trigger שקובע מתי זה רץ; הבאת נתונים, HTTP Request שקורא לכתובת; עיבוד, Edit Fields שיוצר שדה חדש עם ביטוי; ושמירה, Data table שמוסיף שורה חדשה בטבלה" width="1600" height="800" loading="lazy" /></a><figcaption>ארבעה צמתים: מתי, מאיפה, מה עושים עם זה, ולאן זה הולך.</figcaption></figure>

הדוגמה כאן היא זו שבמדריך הרשמי של n8n: workflow שרץ כל בוקר ב-8, מביא את מזג האוויר בברלין משירות נתונים לדוגמה של n8n, הופך אותו למשפט קריא ושומר אותו בטבלה. הבחירה בדוגמה הזו מכוונת: היא לא דורשת חשבון בשום שירות חיצוני, ולכן היא לא נתקעת על הרשאות.

1. **יוצרים workflow.** בתפריט השמאלי בוחרים Personal ואז Create workflow. נפתח הקנבס, המקום שבו בונים.
2. **מוסיפים טריגר.** בוחרים Add first step ואז On a schedule. בשדה Trigger at Hour בוחרים 8am. השאלה הראשונה בכל workflow היא איך הוא מתחיל: לפי זמן, כשמישהו שולח טופס, או כשמגיעה הודעה מאפליקציה.
3. **מביאים נתונים.** לוחצים על הפלוס אחרי הטריגר, מחפשים http ובוחרים HTTP Request. בשדה URL מדביקים את הכתובת `https://mockingbird.n8n.io/v1/weather/berlin` ולוחצים Execute step. בפלט מופיעים השדות `city`, `temp_c` ו-`condition`.
4. **מעבדים.** מוסיפים צומת Edit Fields (Set), לוחצים Add Field וקוראים לשדה `report`. כותבים טקסט, וגוררים לתוכו את השדות מהפלט של הצומת הקודם. n8n עובר אוטומטית למצב Expression, והערך נראה כך:

```text
The temperature in {{ $json.city }} is {{ $json.temp_c }}°C. It's currently {{ $json.condition }}.
```

5. **שומרים.** מוסיפים צומת Data table, בוחרים Insert row, ויוצרים טבלה חדשה עם עמודה בשם `report`. כשבוחרים Map Automatically, n8n ממפה את השדה לעמודה בעצמו, כי השמות זהים.
6. **בודקים ומפרסמים.** לוחצים Execute מתחת לקנבס. כשכל ארבעת הצמתים מסומנים בווי ירוק, בודקים שהשורה נוספה לטבלה, ואז לוחצים Publish.

הביטוי בשלב 4 הוא הכלי החשוב ביותר שתלמדו כאן. `{{ $json.city }}` הוא מקום שמור: כשה-workflow רץ, n8n מחליף אותו בערך האמיתי מהצומת הקודם. כמעט כל workflow שתבנו בהמשך ישתמש בזה.

## מה ההבדל בין הרצה ידנית להרצה אוטומטית?

זה המקום שבו רוב המתחילים נתקעים. לפי התיעוד של n8n יש שלושה סוגי הרצות:

- **הרצה ידנית.** לוחצים Execute workflow על הקנבס ורואים את הנתונים עוברים בין הצמתים. זו בדיקה, והיא רצה רק כשלוחצים.
- **הרצה חלקית.** פותחים צומת אחד ולוחצים Execute step. n8n מריץ את הצומת הזה ואת הצמתים שלפניו שצריך כדי למלא את הקלט שלו. שימושי כשמשנים צומת אחד ורוצים לבדוק אותו שוב על אותם נתונים.
- **הרצת פרודקשן.** קורית לבד, כשהטריגר מופעל. היא דורשת טריגר שאינו הטריגר הידני, ו-workflow מפורסם. ההרצות האלה לא מוצגות בעורך אלא בלשונית Executions של ה-workflow, ובמסלולים בתשלום הן נספרות במכסת ההרצות.

שני דברים שכדאי לזכור: נתונים שנעצתם בזמן הבדיקה לא משפיעים על הרצת פרודקשן, שמביאה נתונים חדשים בכל פעם. והרצה חלקית צריכה טריגר. אם תקבלו הודעה שהצומת לא מחובר לשום טריגר, חברו טריגר ידני והריצו שוב.

## אפשר לבנות workflow בלי לגרור צמתים?

כן. n8n Assistant בונה workflow מתוך תיאור בשפה חופשית: כותבים מה רוצים, מאשרים כל שלב, ומקבלים workflow שאפשר לפתוח, לערוך ולפרסם. לפי המדריך הרשמי, את אותו workflow של מזג האוויר הוא בונה בפחות מחמש דקות. לפי התיעוד, הוא זמין ב-n8n Cloud במסלולים Starter ו-Pro, ובשרת משלכם במהדורות Community, Registered Community ו-Business.

ההמלצה שלנו למתחילים: בנו את ה-workflow הראשון ביד, גם אם יש לכם את ה-Assistant. כשתבינו מה כל צומת עושה ומאיפה מגיע כל ערך, תדעו לבדוק ולתקן את מה שה-Assistant בונה.

## אילו טעויות נפוצות כדאי להכיר?

- **לשכוח לפרסם.** workflow שנבדק ידנית ועובד לא ירוץ לבד עד שמפרסמים אותו.
- **לא לבדוק את אזור הזמן.** לפי התיעוד של צומת Schedule Trigger, הוא משתמש באזור הזמן של ה-workflow אם הוגדר, ואחרת באזור הזמן של ה-instance. בשרת משלכם ברירת המחדל היא America/New_York, ואז "8 בבוקר" מגיע בשעה אחרת לגמרי בישראל.
- **לבנות הכול בבת אחת.** הריצו כל צומת עם Execute step מיד אחרי שהוספתם אותו. טעות שמתגלה בצומת השני קלה לתיקון. טעות שמתגלה אחרי עשרה צמתים לא.
- **להתחיל משירות שדורש הרשאות.** ה-workflow הראשון צריך ללמד את הדפוס, לא את ההרשאות של Google או של Slack. לכן הדוגמה הרשמית משתמשת בשירות נתונים לדוגמה.
- **לשנות את העיר בדוגמה.** שירות הנתונים לדוגמה מחזיר מזג אוויר לכ-40 ערים באירופה בלבד. עיר אחרת תחזיר שגיאה.
