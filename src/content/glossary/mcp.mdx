מה זה MCP? בקצרה: MCP (ראשי תיבות של Model Context Protocol) הוא תקן פתוח שמגדיר איך אפליקציית AI, כמו Claude או Claude Code, מתחברת לכלים ולמקורות מידע חיצוניים. במקום לכתוב חיבור נפרד לכל מערכת ולכל כלי, כל מערכת נחשפת פעם אחת דרך שרת MCP, וכל אפליקציה שתומכת בתקן יכולה להשתמש בו. Anthropic פרסמה את התקן בקוד פתוח בנובמבר 2024.

<div class="definition">**MCP:** פרוטוקול פתוח שמאחד את הדרך שבה מודלי שפה מקבלים הקשר, כלומר מידע וכלים, מהעולם שמחוץ להם. התיעוד של Anthropic משווה אותו ליציאת USB-C לאפליקציות AI: שקע אחד אחיד שמחבר מודלים למקורות מידע ולכלים שונים.</div>

## איזו בעיה MCP פותר?

לפני MCP, כל חיבור בין עוזר AI למערכת נבנה בנפרד. בהודעה על השקת התקן, Anthropic כתבה שכל מקור מידע חדש דרש מימוש מותאם משלו, ולכן קשה היה להרחיב מערכות מחוברות. MCP מחליף את האינטגרציות המפוזרות האלה בפרוטוקול אחד.

המשמעות בארגון: אם יש לכם מערכת כרטיסים, מסד נתונים ותיקיית מסמכים, חיבור כל אחת מהן לשלושה כלי AI שונים כבר לא אומר תשעה פרויקטים נפרדים. בונים או מתקינים שרת לכל מערכת, וכל כלי שתומך בתקן מתחבר אליו.

## איך MCP עובד?

יש שני צדדים. **שרת MCP** חושף מערכת אחת: אילו פעולות אפשר לבצע בה ואיזה מידע אפשר לקרוא ממנה. **לקוח MCP** הוא אפליקציית ה-AI שמתחברת לשרת, למשל Claude Desktop או Claude Code. המודל רואה את רשימת הכלים שהשרת מציע, ומחליט מתי לקרוא להם לפי הבקשה.

לפי התיעוד של ה-MCP connector, Claude קורא לכלי של שרת כשהבקשה מתאימה ליכולת שהכלי מתאר, גם בניסוח ישיר וגם בעקיפין. שאלה כללית על השירות עצמו נענית בלי לקרוא לכלי. כך נראה חיבור ראשון ב-Claude Code:

1. **בוחרים מערכת אחת** שממנה אתם מעתיקים מידע לצ׳אט שוב ושוב. זה בדיוק המצב שבו התיעוד של Claude Code ממליץ לחבר שרת.
2. **מוצאים שרת קיים** ב-Anthropic Directory או אצל ספק המערכת, ובודקים מי מתחזק אותו.
3. **מוסיפים אותו** בפקודה `claude mcp add --transport http <name> <url>`.
4. **בוחרים היקף (Scope).** ברירת המחדל היא מקומית ופרטית לכם. היקף פרויקט שומר את ההגדרה בקובץ `.mcp.json` שאפשר לשתף עם הצוות דרך מערכת ניהול הגרסאות.
5. **מתחברים ומנסים שאלה אמיתית,** ובודקים בתשובה שהמידע הגיע מהמערכת ולא מהזיכרון של המודל.

## מה ההבדל בין MCP, API ושימוש בכלים?

| המונח | מה הוא | מי משתמש בו |
|---|---|---|
| [API](/glossary#api) | ממשק של מערכת אחת, בפורמט שלה | מפתחים שכותבים קוד חיבור |
| [שימוש בכלים](/glossary#tool-use) | היכולת של המודל לבקש להפעיל פונקציה | המודל, דרך האפליקציה שמריצה אותו |
| MCP | תקן אחיד שעוטף מערכות ככלים | כל אפליקציית AI שתומכת בתקן |

בפועל שרת MCP הוא לרוב שכבה דקה מעל API קיים. ה-API לא נעלם. MCP קובע איך המודל מגלה אותו ומשתמש בו.

## מה זה MCP בפועל, בארגון?

נניח שצוות התפעול שואל כל בוקר על פניות פתוחות ומעתיק טבלאות ממערכת הכרטיסים לצ׳אט. עם שרת MCP למערכת, אפשר לשאול את Claude Code ישירות "אילו פניות נפתחו אתמול ועדיין בלי מטפל?", והוא קורא לכלי החיפוש של השרת ועונה מתוך הנתונים העדכניים. אותו שרת יכול לשמש גם [סוכן AI](/glossary/ai-agent) שמסכם את הפניות בסוף היום.

ה-MCP connector של Claude API מאפשר להתחבר לשרתים מרוחקים ישירות מ-Messages API, בלי לבנות לקוח. נכון לעכשיו הוא תומך רק בקריאות לכלים מתוך המפרט, והשרת צריך להיות חשוף ב-HTTP. שרת מקומי שרץ על המחשב לא מתחבר אליו ישירות.

## מה לבדוק לפני שמחברים שרת MCP?

- **מי כתב את השרת.** התיעוד של Claude Code ממליץ לוודא שאתם סומכים על כל שרת לפני החיבור.
- **תוכן חיצוני.** שרת שמביא דפי אינטרנט או מיילים חושף את המודל להזרקת הנחיות. התייחסו לתוכן כזה כנתונים, לא כהוראות.
- **הרשאות.** התחילו בכלים של קריאה בלבד. התיעוד של ה-MCP connector ממליץ לחסום כלים שכותבים או מוחקים כשבונים עוזר לקריאה בלבד, או כשרוצים שאדם יאשר כל שינוי. על הדפוס הזה תמצאו עוד בעמוד על [אדם בלולאה](/glossary/human-in-the-loop).
- **בעלות.** שרת שאיש לא אחראי לו יישבר בשקט כשה-API שמתחתיו משתנה.

עוד על חיבור מערכות קיימות, מנקודת המבט של צוותי IT, במדריך [חיבור מערכות ארגוניות ל-AI](/blog/connect-systems-to-ai). כל המונחים הקשורים נמצאים ב[מילון המונחים](/glossary), והמדריך המלא לעבודה עם הכלי נמצא במרכז הנושא [Claude Code לארגונים](/topics/claude-code).
