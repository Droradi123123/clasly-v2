# Decisions

Decisions made where the brief left room, with the reasoning. Newest last.

1. **Astro over Next.js static export.** Static HTML for every content page, zero JS by default, first-class MDX and content collections, and the Cloudflare adapter lets the three API routes live in the same project. Next.js static export cannot host the streaming endpoint without a separate server; Astro + the Cloudflare adapter can.
2. **Cloudflare Workers (static assets) instead of Cloudflare Pages.** Astro 6+ only ships a Workers-based Cloudflare adapter, and Cloudflare now recommends Workers with static assets for new projects. Preview deployments per PR still work through Workers Builds. The brief's "Pages" intent (static hosting + edge functions + PR previews) is fully met.
3. **Astro 7 on Node 24.18.0.** Astro 7 requires Node >= 22.23.4. `.node-version` pins 24.18.0 because the Cloudflare Workers Builds image preinstalls 24.18.0 (and 22.23.2, which is too old for Astro), so builds start without a custom Node install. CI uses the same file.
4. **API routes inside Astro (`src/pages/api/*`) rather than a separate Worker.** One deploy, shared config (`src/config/site.ts`), shared types. Secrets are read via `cloudflare:workers` `env`.
5. **Rate limiting and prompt cache in Workers KV** (`AGENT_KV`), fixed window per IP (8 outlines/hour, 5 leads/hour, 120 events/hour). Falls back to an in-memory map locally so dev works without bindings.
6. **Outline model: `claude-opus-5-5` at `effort: low`, streaming, system prompt cached.** Streaming gets the first tokens on screen in about a second and the full outline well inside five seconds. The model is configurable via the `OUTLINE_MODEL` var; `claude-haiku-5-5` is the cheaper swap if volume grows and quality holds.
7. **Cheap moderation before the LLM**: length cap (300 chars), URL/script/prompt-injection patterns, minimum letter ratio. The system prompt also instructs the model to fall back to a generic outline for off-topic input, so no second model call is needed.
8. **Anonymized agent logging**: `agent_sessions` stores prompt, outline, page, cache hit and a truncated IP hash only. No names or contacts are collected with it. `converted` flips when the visitor taps WhatsApp or copies the outline.
9. **Email notifications via Resend's HTTP API** (one `fetch`, no SDK). Swappable in `src/lib/notify.ts`. Skipped silently until `RESEND_API_KEY` and `CONTACT_EMAIL` are set.
10. **Turnstile is optional until configured**: when `TURNSTILE_SECRET_KEY` is missing the form still works (honeypot + rate limit only), so the site is testable before the Cloudflare setup is complete.
11. **Admin leads page uses HTTP Basic auth** (`ADMIN_PASSWORD`), `noindex`, excluded from the sitemap and robots. Simplest protected page with zero dependencies; replace with Cloudflare Access when there are several users.
12. **OG images are generated after build with sharp** (`scripts/og.mjs`), by scanning the built HTML for title/description/og:image. Hebrew is shaped correctly by librsvg/pango; the bundled Heebo WOFF is converted to TTF on the fly because FreeType cannot read WOFF2. No satori (weak RTL support) and no runtime image endpoint (cost, latency).
13. **Slugs are short English** (`/lectures`, `/topics/claude-code`, `/blog/n8n-ai-agent`) for clean, shareable URLs; titles and content are Hebrew.
14. **Theme: dark-first with a light mode**, one accent (`#5ee1c3` / `#0f9d7f`), self-hosted Heebo variable font with the Hebrew subset first. Theme preference is stored in `localStorage`, applied inline to avoid a flash.
15. **Reveal animations are JS-gated** (`html.js .reveal`), so content is fully visible without JavaScript and for crawlers.
16. **Testimonials sections are reserved but not rendered** (HTML comments in `index.astro`, `academia.astro`, `companies.astro`) until genuine quotes exist. No invented quotes, no Review schema.
17. **Topic hubs**: 7 hub routes exist; 3 (Claude Code, n8n, AI agents) carry full pillar content from `src/content/hubs`. The other 4 render a lighter hub (title, article list, CTA) until their pillar content is written, so internal links never 404.
18. **No `/case-studies` yet** (phase 2 per the brief); the data model (`leads`, `events`) already supports reporting outcomes.
19. **Old uploads archived**: the two `clasly-main*.zip` files that were in the repo (an unrelated Lovable/Vite project) were moved to `_archive/` untouched rather than deleted.
20. **Sitemap `changefreq`**: weekly for blog and topics, monthly for the rest; `lastmod` is left to the content's visible "last updated" dates and the Article schema.
21. **Supabase: shared "Lecture" project, tables prefixed `site_`.** The account's free tier allows two active projects and both were taken, so a dedicated project could not be created. The schema was applied to the existing "Lecture" project (same business domain) as additive tables `site_leads`, `site_agent_sessions`, `site_events` and the view `site_agent_prompts_daily`, all with RLS on and no public policies. Nothing in that project was modified. Moving to a dedicated project later is a matter of re-running the migration there and changing two secrets.
22. **Own sitemap endpoints instead of `@astrojs/sitemap`.** The brief asks for sitemaps split by type with accurate dates. `/sitemap-index.xml` points to `/sitemaps/pages.xml`, `/sitemaps/topics.xml`, `/sitemaps/blog.xml`; `lastmod` comes from content frontmatter (articles, hubs) and from `updatedAt` on offer pages. `/sitemap.xml` redirects to the index for tools that expect it.
23. **GEO extras**: every page carries a `WebPage` node with `dateModified`; articles carry `speakable` (lead + first paragraph); the Organization is typed `Organization` + `EducationalOrganization`; blog and topics indexes carry `CollectionPage` + `ItemList`; the homepage has a FAQ with `FAQPage` schema; `/glossary` publishes 36 definitions with `DefinedTermSet` schema so answer engines can quote one-sentence definitions with attribution.
24. **Security headers via `public/_headers`** (nosniff, referrer policy, permissions policy, frame options, HSTS). No CSP yet: Turnstile, Cloudflare Insights and the inline theme script would need nonces; listed in TODO.
25. **CI on GitHub Actions**: content checklist, `astro check`, build, and a smoke test that robots, sitemap, llms.txt and OG images exist in the output. Cloudflare Workers Builds handles deploys and PR previews separately.
26. **Brand: RealAI, domain realai.co.il** (chosen by the owner). The wordmark is rendered from `BRAND_NAME` with a trailing "AI" in the accent colour, always written as RealAI with two capitals so the lowercase domain reads correctly. Canonical host is the apex `https://realai.co.il`.
27. **Brand suffix in `<title>` only when it fits**: pages get ` | RealAI` appended only if the full title stays within 60 characters; longer titles keep the keyword-bearing title intact. Open Graph titles never carry the suffix (the OG image and `og:site_name` show the brand).
28. **Worker name `clasly-v2`.** The Worker was created from the dashboard with the repository's name. Workers Builds requires the `name` in `wrangler.jsonc` to match the dashboard Worker, so the config follows the dashboard. The name is internal only; visitors see realai.co.il.
29. **Leads moved from Supabase to Cloudflare D1** (owner's choice, 2026-10-24). Everything now lives in one Cloudflare account: no second service, no service-role key to copy, and the database is reachable only through the Worker binding `DB`, so no row-level security layer is needed. The schema is in `migrations/` and tracked by `wrangler d1 migrations`. Removing `@supabase/supabase-js` also cut about 720 KiB from the Worker bundle. Decisions 8 and 21 above describe the earlier Supabase setup and are superseded by this one.
30. **The lead form never fakes success.** If the database binding is missing or the insert fails, the API returns an error and the form shows a Hebrew message pointing to WhatsApp or email, instead of "thanks" for a lead that was lost.
31. **Hero outline builder removed** (owner's decision, 2026-10-24). The owner did not connect with the "type a sentence, get an outline" agent, so the component, `/api/outline`, its prompt and moderation code are gone. The site no longer needs an Anthropic API key at runtime; the SDK stays as a dev dependency for `scripts/new-article.mjs --ai`. The empty `agent_sessions` table in D1 is left in place and unused. Decision 6 and 7 are superseded.
32. **Homepage message: "Implementing AI is hard. We did it."** The core story is the gap between people who learned AI from videos and people who implemented it in organizations of thousands of employees. The hero states it in one line; a dedicated section contrasts the two lists. No competitor is named.
33. **Visual direction v2**: deeper near-black base, mint accent with a violet partner used only in gradients, very large display type, slowly drifting aurora behind a fading grid, a hand-drawn underline that draws itself under one word, cards with a gradient border and a cursor spotlight, and a struck-through list in the gap section. All motion is CSS (transform, opacity, stroke-dashoffset) and is switched off under `prefers-reduced-motion`.
34. **Client logos as a slow endless marquee** (about 90 seconds per loop, pauses on hover). The list repeats so even five logos fill the row. Official logo files are still needed; the network in the build environment blocks the sources, so the placeholders remain until the files are provided.
35. **No durations on the homepage offer cards.** Programs are presented as open and built around the organization. Offer pages still describe typical formats in their logistics sections.
36. **Founder playbook as the source of truth for adoption content.** `content/source/ai-adoption-playbook.md` holds the team's own methodology. The AI adoption pillar was rewritten from it (with HowTo structured data for the three stages), and ten articles expand its sections, one focus phrase each. These pieces use no invented statistics or client stories; examples are labelled as examples. Articles written earlier by content agents still contain composite figures and remain on the editorial-review list in TODO.md.
37. **Worker renamed to `realai`** (owner's request). The Worker is renamed in the Cloudflare dashboard first, then `wrangler.jsonc` follows, because Workers Builds requires the two names to match. Supersedes decision 28.
